# Requirements: Epstein Investigation Platform — Phase 2

**Defined:** 2026-03-07
**Core Value:** An investigator can search, connect, and analyze 1.5M documents to discover relationships and patterns that would be impossible to find manually.

### AI Chat

- [ ] **CHAT-01**: User can chat with Claude via Anthropic SDK routed through Cloudflare AI Gateway
- [ ] **CHAT-02**: User can select Claude model (default Sonnet 4.6, option for Opus) in chat settings
- [ ] **CHAT-03**: Claude uses search_documents tool to query PostgreSQL full-text search during conversation
- [ ] **CHAT-04**: Claude uses semantic_search tool to query Qdrant vector similarity during conversation
- [ ] **CHAT-05**: Claude uses get_entity_profile tool to retrieve entity data from Neo4j during conversation
- [ ] **CHAT-06**: Claude uses graph_query tool to traverse Neo4j relationships during conversation
- [ ] **CHAT-07**: Claude uses find_connections tool to discover paths between entities during conversation
- [ ] **CHAT-08**: User sees streaming SSE responses as Claude generates text and calls tools
- [ ] **CHAT-09**: Every AI claim displays inline document ID citations that link to the document viewer
- [ ] **CHAT-10**: Chat context uses sliding window (last 6 messages + current turn tools) to control token costs
- [ ] **CHAT-11**: AI-generated content displays disclaimer that it is AI-generated and may contain errors

### Entity Dossiers

- [ ] **ENTY-01**: Entity page displays header with name, type, aliases, document mention count, and connection count
- [ ] **ENTY-02**: Entity page has documents tab showing all documents that mention the entity with search/filter
- [ ] **ENTY-03**: Entity page has connections tab showing Neo4j neighbors with relationship types and weights
- [ ] **ENTY-04**: Entity page has timeline tab showing entity-related events in chronological order
- [ ] **ENTY-05**: Entity page has AI biography generated by Claude synthesizing corpus mentions, cached per entity
- [ ] **ENTY-06**: User can add, edit, and delete analyst investigation notes on any entity

### Faceted Search

- [x] **SRCH-01**: User can filter search results by document content classification (court filing, correspondence, financial, etc.)
- [x] **SRCH-02**: User can filter search results by entity mentions (select entities to require in results)
- [x] **SRCH-03**: User can filter search results by date range using presets (year, decade) and custom range
- [x] **SRCH-04**: User can save a search query with filters and re-execute it later from a saved searches list
- [x] **SRCH-05**: User can export current search results to CSV or JSON format

### Graph Analysis

- [x] **GRPH-01**: User can run PageRank on the entity graph to identify most connected/influential entities
- [x] **GRPH-02**: User can run Louvain community detection to identify entity clusters
- [x] **GRPH-03**: User can run betweenness centrality to identify bridge nodes between communities
- [x] **GRPH-04**: User can discover hidden connections — entity pairs with shared neighbors but no direct edge
- [ ] **GRPH-05**: Graph visualization reflects algorithm results via node size (centrality) and color (community)

### Timeline

- [ ] **TIME-01**: Date extraction pipeline processes documents to extract event dates with type and confidence
- [ ] **TIME-02**: User can view an interactive zoomable timeline (decade to day granularity) of extracted events
- [ ] **TIME-03**: User can filter timeline by entity to see only events involving selected entities

### Document Analysis

- [ ] **DOCS-01**: Redaction detection pipeline identifies [REDACTED], [SEALED], and blackout patterns in documents
- [ ] **DOCS-02**: User can view redaction annotations on document pages with inconsistency flags
- [ ] **DOCS-03**: Cross-reference resolution pipeline links exhibit references and Bates numbers across documents
- [ ] **DOCS-04**: User can navigate cross-references from one document to linked documents

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Real-time collaboration | Solo investigator platform behind Cloudflare Access — zero users need this |
| Public user registration | Sensitive investigation data — no public access, Cloudflare Access single-user gate |
| Multi-tenancy / RBAC | One user — adding user management is pure scope creep |
| Mobile app | Investigation work happens at a desk with multiple monitors, not on a phone |
| New batch ingestion automation | Current manual process works — automate when volume demands it |
| Medium/Low code review findings | Lower risk, address incrementally during feature work |
