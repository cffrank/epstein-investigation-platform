Create `frontend/src/lib/server/tools/` directory with 6 files.

**search-documents.ts** — Full-text search via PostgreSQL:
- Tool name: `search_documents`
- Description: "Search the Epstein investigation document corpus using full-text search. Returns matching documents with highlighted excerpts."
- Input schema: `{ query: string (required), limit?: number (max 25, default 10) }`
- Handler: Uses `query()` from `$lib/server/db` with `plainto_tsquery` and `ts_headline` for excerpts. SQL: `SELECT id, filename, source, ts_headline('english', COALESCE(metadata->>'text',''), plainto_tsquery('english', $1), 'MaxWords=200, MinWords=50') as excerpt FROM documents WHERE search_vector @@ plainto_tsquery('english', $1) ORDER BY ts_rank(search_vector, plainto_tsquery('english', $1)) DESC LIMIT $2`
- Returns: Array of `search_result` blocks. Each has `source: '/documents/{id}'`, `title: filename`, `content: [{type: 'text', text: excerpt}]`, `citations: {enabled: true}`

**semantic-search.ts** — Vector similarity via Qdrant:
- Tool name: `semantic_search`
- Description: "Search documents using semantic similarity. Finds conceptually related content even without exact keyword matches."
- Input schema: `{ query: string (required), limit?: number (max 20, default 8) }`
- Handler: First generates embedding by calling the backend API (`${API_BASE_URL}/api/embeddings` with the query text). Then calls `qdrantClient().search()` with the vector. Fetches document metadata from PostgreSQL for matched doc IDs.
- Returns: Array of `search_result` blocks with similarity score in the content text.
- NOTE: For embedding generation, call `${platform.env.API_BASE_URL}/api/embeddings` POST with `{text: query}` and `X-API-Key` header. If that endpoint doesn't exist, fall back to calling the Cloudflare Worker's `/ai/embedding` endpoint.

**get-entity-profile.ts** — Entity lookup via Neo4j:
- Tool name: `get_entity_profile`
- Description: "Get a detailed profile of a person, organization, or location from the knowledge graph, including connections and document mentions."
- Input schema: `{ name: string (required), type?: 'Person' | 'Organization' | 'Location' }`
- Handler: Uses `neo4jClient().query()` with parameterized Cypher. Query: `MATCH (e) WHERE toLower(e.name) CONTAINS toLower($name) AND ($type IS NULL OR $type IN labels(e)) WITH e LIMIT 1 OPTIONAL MATCH (e)-[r]-(connected) RETURN e, collect(DISTINCT {type: type(r), target: connected.name, targetLabels: labels(connected)}) as connections LIMIT 1`. Format entity properties and connections as readable text.
- Returns: Single `search_result` block with entity profile as content.

**graph-query.ts** — Graph traversal via Neo4j:
- Tool name: `graph_query`
- Description: "Traverse relationships in the knowledge graph. Find entities connected to a given entity by specified relationship types."
- Input schema: `{ entity_name: string (required), relationship_type?: string, max_depth?: number (1-3, default 1), limit?: number (max 50, default 20) }`
- Handler: Parameterized Cypher traversal. Build query dynamically based on depth and relationship type, but ALWAYS use parameters for entity_name (never string interpolation — CR-002 fix). Format results showing entity -> relationship -> connected entity chains.
- Returns: Array of `search_result` blocks, one per connected entity with its relationship context.

**find-connections.ts** — Path finding via Neo4j:
- Tool name: `find_connections`
- Description: "Discover connections between two entities in the knowledge graph. Finds shortest paths and shared associations."
- Input schema: `{ entity_a: string (required), entity_b: string (required), max_path_length?: number (2-6, default 4) }`
- Handler: Parameterized Cypher shortest path: `MATCH (a), (b) WHERE toLower(a.name) CONTAINS toLower($a) AND toLower(b.name) CONTAINS toLower($b) WITH a, b LIMIT 1 MATCH path = shortestPath((a)-[*..{maxLen}]-(b)) RETURN path`. Format path as readable chain.
- Returns: `search_result` block with path description. If no path found, return text explaining no connection found.

**index.ts** — Tool registry:
- Export `toolDefinitions`: array of all 5 Anthropic.Messages.Tool objects
- Export `executeTool(name: string, input: unknown, platform: App.Platform): Promise<SearchResultBlock[]>` — switch on tool name, call the appropriate handler, handle errors gracefully (return error text as search_result if tool fails).
- Import types from `@anthropic-ai/sdk` for type safety.

IMPORTANT: All Cypher queries MUST use parameterized values (never string concatenation). This is a security requirement from CR-002.
IMPORTANT: Cap all result text to ~1500 chars per search_result to avoid blowing up context.
