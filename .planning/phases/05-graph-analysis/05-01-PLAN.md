  <name>Task 1: Install GDS plugin and create batch computation endpoint</name>
  <files>docker-compose.yml, frontend/src/routes/api/graph/compute/+server.ts</files>
  <action>
1. In docker-compose.yml, change `NEO4J_PLUGINS: '["apoc"]'` to `NEO4J_PLUGINS: '["apoc","graph-data-science"]'`. This is the only change to docker-compose.yml.

2. Create `frontend/src/routes/api/graph/compute/+server.ts` with a POST handler that:
   - Imports `neo4jClient` from `$lib/server/neo4j`
   - First checks for and drops any stale projection named 'entity-analysis': `CALL gds.graph.list() YIELD graphName WHERE graphName = 'entity-analysis' CALL gds.graph.drop(graphName) YIELD graphName AS dropped RETURN dropped` (catch and ignore errors if not exists)
   - Projects the entity subgraph: `CALL gds.graph.project('entity-analysis', ['Person', 'Organization', 'Location'], { ALL: { type: '*', orientation: 'UNDIRECTED' } })`
   - Runs PageRank: `CALL gds.pageRank.write('entity-analysis', { writeProperty: 'pagerank', maxIterations: 20, dampingFactor: 0.85 })`
   - Runs Louvain: `CALL gds.louvain.write('entity-analysis', { writeProperty: 'communityId' })`
   - Runs Betweenness with sampling: `CALL gds.betweenness.write('entity-analysis', { writeProperty: 'betweenness', samplingSize: 1000, samplingSeed: 42 })`
   - Drops the projection: `CALL gds.graph.drop('entity-analysis')`
   - Stores computation timestamp: `MERGE (m:Metadata {key: 'algorithm_last_computed'}) SET m.value = toString(datetime())`
   - Wraps everything in try/catch with a finally block that attempts to drop the projection (prevents memory leaks on error)
   - Returns `{ success: true, timestamp: string }` on success or `{ error: string }` with status 500 on failure
  </action>

<task type="auto">
  <name>Task 2: Add algorithm result query actions to graph API</name>
  <files>frontend/src/routes/api/graph/+server.ts</files>
  <action>
Extend the existing POST handler's switch statement with five new actions:

1. **'pagerank' action**: Query `MATCH (n) WHERE n.pagerank IS NOT NULL RETURN id(n) as id, labels(n)[0] as type, n.name as name, n.pagerank as pagerank, n.communityId as communityId, n.betweenness as betweenness, COUNT { (n)--() } as connections ORDER BY n.pagerank DESC LIMIT $limit` with `limit` param defaulting to 25. Return `{ results: Array<{ id, type, name, pagerank, communityId, betweenness, connections }> }`.

2. **'communities' action**: Query `MATCH (n) WHERE n.communityId IS NOT NULL RETURN id(n) as id, labels(n)[0] as type, n.name as name, n.communityId as communityId, n.pagerank as pagerank, n.betweenness as betweenness, COUNT { (n)--() } as connections ORDER BY n.pagerank DESC LIMIT $limit` with limit defaulting to 25. Also query community sizes: `MATCH (n) WHERE n.communityId IS NOT NULL RETURN n.communityId as communityId, count(*) as size ORDER BY size DESC LIMIT 8`. Return `{ results: [...], communitySizes: Array<{ communityId, size }> }`.

3. **'bridges' action**: Query `MATCH (n) WHERE n.betweenness IS NOT NULL RETURN id(n) as id, labels(n)[0] as type, n.name as name, n.betweenness as betweenness, n.pagerank as pagerank, n.communityId as communityId, COUNT { (n)--() } as connections ORDER BY n.betweenness DESC LIMIT $limit` with limit defaulting to 25. Return `{ results: [...] }`.

4. **'hidden-connections' action**: Query `MATCH (a:Person)-[]->(shared)<-[]-(b:Person) WHERE NOT (a)-[]-(b) AND id(a) < id(b) WITH a, b, collect(DISTINCT shared) as sharedNodes, count(DISTINCT shared) as cnt WHERE cnt >= 3 RETURN id(a) as personAId, a.name as personAName, id(b) as personBId, b.name as personBName, cnt as sharedCount, [s IN sharedNodes[0..10] | {id: id(s), name: s.name, type: labels(s)[0]}] as topSharedNeighbors ORDER BY cnt DESC LIMIT 20`. Return `{ pairs: Array<{ personAId, personAName, personBId, personBName, sharedCount, topSharedNeighbors }> }`.

5. **'algorithm-status' action**: Query `MATCH (m:Metadata {key: 'algorithm_last_computed'}) RETURN m.value as lastComputed` and also `MATCH (n) WHERE n.pagerank IS NOT NULL RETURN count(n) as count`. Return `{ lastComputed: string | null, nodeCount: number }`.

For all actions, also update the existing 'search' and 'neighbors' actions to include algorithm properties (pagerank, communityId, betweenness) in returned node data when those properties exist on the nodes. This ensures nodes loaded via search/expand also carry their algorithm scores for visualization.

Specifically in the 'search' action, change the RETURN clause to include `n.pagerank as pagerank, n.communityId as communityId, n.betweenness as betweenness` and map them into the node data object. Similarly in 'neighbors', add `m.pagerank as pagerank, m.communityId as communityId, m.betweenness as betweenness` to the RETURN and map into target node data.
